# 이미지 제작 목록 — Step 17A

> 최신 콘텐츠 구성은 적2종·중간보스·최종보스·3스테이지다([진행 구성](STAGE_PLAN.md)). 아래3종/2스테이지 수량표는 초기 제작량 산정 기록이며 현재 필수 자산 목록이 아니다. 현재 플레이어는8×2 시트, 탄환/노이즈는절차적셰이더를사용한다. 추가이미지제작은사용자가진행하며기존자산을재사용해시스템부터구현한다.

이미지는 사용자가 직접 제작한다. 아래 수량은 **플레이어1, 일반 적3종, 보스2종, 스테이지2개**를 가정한 초안이다. 콘텐츠 수는 아직 확정하지 않았다. 기본 창의 게임 영역은 사용자 요청으로1920×1080(Full HD)으로 정했다. 기존 에이전트 생성 마법사 시안은 적용하지 않는다.

## 파일 및 시트 규격 초안

- `player_sheet.png`: 셀256×256, 6열×3행. 행별 기본/왼쪽/오른쪽, 각 행 왼쪽→오른쪽6프레임. 전체1536×768.
- `enemy_01_sheet.png`, `enemy_02_sheet.png`, `enemy_03_sheet.png`: 각 셀128×128, 4열×2행, 행 우선8프레임. 전체512×256.
- `boss_01_sheet.png`, `boss_02_sheet.png`: 각 셀256×256, 8열×2행. 기본/시전 각8프레임. 전체2048×512.
- `bullets_sheet.png`: 셀64×64, 4열×4행. 종류별 한 행, 각4프레임. 전체256×256. 단순 탄환은1프레임으로 줄일 수 있다.
- `effects_sheet.png`: 셀128×128, 8열×5행. 효과별 한 행, 각8프레임. 전체1024×640. 커다란 보스 효과는 필요 시 별도 큰 셀 시트로 분리한다.
- `particles_sheet.png`: 셀64×64, 3열×1행. 전체192×64. 파티클의 이동/회전/확대/페이드는 코드에서 표현한다.
- `dissolve_noise.png`: 256×256 회색조. 흰색/검정 단순 이진 패턴보다 중간 밝기가 이어지는 노이즈를 준비한다. 캐릭터마다 사망 프레임을 만들지 않고 셰이더로 소멸시킨다.
- `stage_01_base.png`, `stage_02_base.png`: 720×960(3:4) 전투 영역에 맞춘 세로 스크롤 배경. 같은 비율의 더 큰 원본도 가능하다. 반복할 경우 위/아래 경계가 자연스럽게 이어져야 한다.
- `stage_01_foreground.png`, `stage_02_foreground.png`: 투명 배경의 전경/장식 레이어. 플레이 영역 비율 및 반복 방향은 base와 맞춘다.
- `title_background.png`, `result_background.png`: 전체 화면 배경. 기본 게임 영역1920×1080의16:9 비율로 제작한다. 글자를 그림에 합치지 않는다.
- `ui_panel.png`, `ui_button.png`: 투명 테두리를 포함한 공용 UI 자산. 버튼 일반/선택/눌림은 우선 Tint/크기 변화로 표현한다. 9-slice 처리는 아직 구현되지 않았다.
- `portrait_player.png`, `portrait_boss_01.png`, `portrait_boss_02.png`: 예시512×512, 초상화/결과 연출에 활용. 대화 시스템 구현을 전제하지 않는다.

## 공통 제작 규칙

- 캐릭터/탄환/효과/파티클은 투명 배경 PNG. 셀마다 같은 시점, 배율, 조명, 중심 기준을 유지한다.
- 프레임마다 인물 중심과 발/몸통 기준이 흔들리지 않아야 한다. 동일 셀 크기만으로 중심 정렬이 보장되지는 않는다.
- 셀 밖으로 모자/무기/이펙트가 잘리지 않게 여백을 둔다. Linear 샘플링에서 인접 셀을 읽는 문제는 UV 안쪽 보정 또는 패딩으로 적용 단계에서 처리한다.
- 처음/끝 프레임은 반복 재생 시 연결되도록 만든다. 시전/명중처럼 일회성 효과는 반복 루프가 아니다.
- 이미지 크기와 표시 크기는 별개다. 셀256×256을 화면에서128×128로 그릴 수 있다. 게임 해상도를 높일 때 표시 크기도 함께 검토하며 비정사각형 인물은 원래 비율을 유지한다.
- 현재 uvRect는 단일 프레임 선택에 활용 가능하다. 애니메이션 타이머/상태/루프 여부/시트 정보는 아직 추가 구현이 필요하다.
- 공격 패턴별로 탄환 그림을 만들 필요는 없다. 방향/배치/속도/회전/Tint로 같은 원본을 재사용한다. 보스 페이즈도 꼭 별도 외형을 요구하지 않는다.

## 제작 순서

### 현재 배경 스크롤 실습용 추천

> 최신확정: 스테이지별배경대신공용마법숲bg0.png와투명안개bg1.png를사용한다. 두원본은941×1672이며비율을보존해게임에연결했다. 아래3단계배경컨셉은이전추천기록이다.

- 아래 컨셉은 추천이며 사용자 확정 사항이 아니다.1스테이지는어두운마법숲,2는고대마법유적,3은마력폭풍속공중성소로 분위기를 강화한다. 먼저1장만 준비한다.
- 전투 영역용3:4 불투명PNG:720×960 또는원본1440×1920. 애니메이션시트는필요없다.
- 위/아래끝이연결되는세로반복이미지로만든다. 하늘/수평선/강한원근이있는풍경화보다는고정시점으로내려다본지면이나구름층이반복에적합하다. 같은이미지를세로로두장붙여경계를확인한다.
- 중앙은낮은대비/낮은채도로유지하고나무·기둥·빛나는문양은측면에배치한다. 밝은점이나탄환처럼작은빛무리는피한다. 배경밝기와Tint는게임에서추가조정가능하다.
- 첫실습은동일배경2개를연속으로그리는단일레이어스크롤이다. 이후별도투명구름/안개레이어를다른속도로움직이는패럴랙스를추가할수있다. 현재스크롤코드는미구현이다.

우선 `player_sheet.png`, `enemy_01_sheet.png`, `bullets_sheet.png`의3개로 애니메이션과 가독성을 검증한다. 규격이 맞으면 나머지를 제작한다. 초상화3개, 투명 전경2개, 패널/버튼2개는 후순위이며 이7개를 일단 생략하면14개 PNG/정지 그림 및 프레임138개다.
