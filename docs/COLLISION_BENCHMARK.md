# Collision Benchmark

## 목적과 실행

고정 256-slot 탄환 풀에서 한 플레이어의 원형 Hit/Graze 검사를 비교한다. 실제 피해, 점수 변경, 렌더링은 수행하지 않는다.

```powershell
cmake --preset msvc-release
cmake --build --preset build-release --parallel
.\out\build\msvc-release\Release\CollisionBenchmark.exe
```

측정 코드는 `tools/collision_benchmark.cpp`이며, 게임과 같은 `Collision.cpp` 및 `UniformGrid.cpp`를 사용한다.

## 측정 방법

- 화면 1280×720, 셀 64px, Grid 20×12, 플레이어 위치 (640,360).
- 풀 256개 중 활성 적 탄환을 32/128/256개로 구성한다. 게임의 실제 탄막 기록이 아닌 고정 합성 배치다.
- 플레이어 Hit 반경 5px, Graze 반경 24px, 적 탄환 반경 8px.
- 전체 순회: 256 슬롯을 훑고 활성 적 탄환만 두 원 판정에 전달한다.
- Grid: 매 반복 Clear와 활성 적 탄환 Insert 후 플레이어 주변 3×3 셀을 검사한다. 생성자 비용은 포함하지 않는다.
- 측정 전에 Hit/Graze 개수가 같은지 확인한다. 서로 다르면 종료 코드 1로 실패한다.
- 셀 저장 공간을 워밍업한 뒤 방법별 20,000회 반복 × 5라운드. 라운드마다 두 방법의 측정 순서를 교대한다.
- `std::chrono::steady_clock`의 시작/종료 차이를 마이크로초로 변환하고 반복 횟수로 나눠 업데이트 1회당 평균을 얻는다.
- 결과를 누적하여 출력 외부에 보관하고 쿼리 함수 인라인을 MSVC에서 막아 반복 측정의 계산이 제거되는 것을 억제한다.

## 2026-10-05 첫 측정

현재 개발 PC, MSVC 19.41, x64 Release. 시간은 마이크로초(µs) 단위다.

| 활성 적탄 | 전체 순회 후보 | Grid 후보 | 전체 순회 시간 | Grid 구성+조회 시간 | Hit | Graze |
|---:|---:|---:|---:|---:|---:|---:|
| 32 | 32 | 6 | 0.228 | 0.398 | 2 | 1 |
| 128 | 128 | 22 | 0.595 | 0.598 | 3 | 2 |
| 256 | 256 | 40 | 1.083 | 0.926 | 3 | 5 |

첫 측정에서 32개는 전체 순회가 빠르고 128개는 거의 같으며 256개는 Grid가 약간 빠르다. 후보 수 감소가 같은 비율의 실행 시간 감소를 뜻하지 않는다.

이 결과는 특정 배치의 작은 CPU 작업에 대한 평균이다. 분산/최악 시간, 다른 탄막 분포, 여러 플레이어, Grid 크기 변화, 전체 프레임 시간과 GPU 비용을 대표하지 않는다. Grid 셀 버퍼 최초 할당 비용도 워밍업에 포함되어 측정에서 제외된다. 게임 적용 효과를 판단하려면 실제 게임의 부하와 전체 프레임 비용을 함께 봐야 한다.
