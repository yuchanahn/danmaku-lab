## 성능 자료의 조건

1. 현재 콘텐츠와 설정을 포함하는 기준 커밋을 확보하고 개선 커밋과 함께 기록한다. 기존 푸시된 버전과 로컬 변경을 혼동하지 않는다.
2. CPU/GPU/RAM/OS, Release 설정, 해상도, VSync OFF, Debug Layer OFF, 계측 도구를 표기한다.
3. 같은 패턴·활성 탄환 수·플레이어 위치·후광 설정을 재현할 방법을 구현한다. 경과 시간만 같다고 같은 장면이라고 가정하지 않는다.
4. 워밍업, 측정 시간, 반복 횟수, 타이머 단위·오버헤드를 실제 방법에 맞춰 기록한다. CPU 렌더 제출, GPU 구간, 프레임 시간은 서로 다른 지표다.
5. 화면 녹화는 계측에 영향을 줄 수 있으므로 수치용 실행과 시연용 녹화를 구분한다. GIF 재생 속도로 성능 향상을 주장하지 않는다.
6. 평균 FPS 외에 프레임 시간 중앙값·P95, Draw·업로드 횟수와 활성 수를 함께 남긴다. 로그와 집계 원본을 보관한다.
7. Grid는 후보 수와 시간 결과를 별도로 기록하고 구축 비용을 포함한다. 후보 수 감소를 그대로 속도 개선으로 적지 않는다.

## 제출 전에 교체할 텍스트

- 개발 시작·종료 날짜, 전체 영상·실행 파일 링크, 최종 기준 커밋.
- 모든 대괄호 자리, 구현 예정 표기, 미확정 모델/도구/규칙.
- 직접 구현 / AI 보조 구현 / 직접 분석·수정·검증 범위를 커밋과 학습 기록으로 확정.
- 실제 실험에서 나온 결과·미채택 대안·남은 제한. 향후 결과를 과거형으로 미리 작성하지 않는다.
- BGM·배경·발사음·폰트 등의 출처와 라이선스. ComfyUI 이미지 제작과 외부 음원을 구분.

완성본에서는 편집 안내를 제거하고 실제 결과로 교체한다. 기능이 미완료 상태로 남는다면 그 항목의 완료 주장과 성과 문장을 제거하거나 제한으로 명시한다.
