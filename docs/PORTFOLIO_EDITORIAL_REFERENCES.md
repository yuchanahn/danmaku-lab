## 원고의 편집 기준

- 첫 화면은 게임 한 문장, 대표 GIF, 소스·영상·실행 링크, 최소 환경 표로 구성한다.
- 구현 항목은 장면 → 실제로 처리해야 했던 조건 → 선택과 이유 → 코드 토글 순서로 쓴다. 모든 항목에 같은 '문제/해결/성과' 소제목을 반복하지 않는다.
- 신입 수준에서 직접 설명 가능한 데이터 전달, 리소스 소유권, 객체 수명, 입력·시간, 충돌과 측정 사례를 사용한다. 경험하지 않은 팀 협업·3D·상용 엔진 경험을 주장하지 않는다.
- 현행 코드 19개 토글은 저장소 함수/구조의 실제 발췌다. 주변 선언을 생략했다는 것을 밝힌다.
- 미래 항목은 구현 예정 표기와 구체적인 결과·코드·자료 슬롯을 둔다. 성능 수치, 실패한 실험, 제작에 쓰지 않은 도구 이름을 만들어 넣지 않는다.
- ComfyUI 이미지 생성 → 영상 생성 → 프레임 추출 → 시트 변환을 사용자의 실제 제작 방식으로 기록한다. 모델/워크플로/명령은 확인 후 추가한다. 외부 CC0 BGM과 구분한다.
- 사진·영상·GIF는 이번 작업에서 생성하지 않는다. 원고의 V01~V13, S01~S11을 후속 제작 기준으로 삼는다.

### 우리 문서에 대한 판단

- 메인 페이지는 대표 장면과 핵심 사례 2~3개를 빠르게 찾을 수 있어야 한다. 현재13개 파트 원고는 상세 재료를 모은 형태이므로 제출본에서는 메인 요약과 상세 페이지/토글의 읽기 단계를 더 명확히 나누는 것이 좋다.
- 영상과 사진은 해당 문장의 증거가 되어야 한다. 캐릭터 애니메이션, 디졸브, 렌더링 개선에 각각 그 차이를 보이는 장면을 붙인다.
- 기술 이름과 코드 분량보다 실제 문제·선택 근거·검증을 보여준다. 성능 그래프는 동일 조건과 원본 로그를 함께 남긴다.
- Notion은 정리 수단이다. 보기 좋은 카드, 많은 이모지, 긴 토글 자체를 구현 역량이나 채용 성과로 취급하지 않는다.
- 이번 요청은 사례 조사와 링크 제공이다. Notion 원고 구조를 추가로 바꾸거나 게임 코드를 수정하지 않았다.
