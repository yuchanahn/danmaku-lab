## 단계 운영 규칙

- 2026-10-06 상세 문서 편집: 이 페이지는 이미 프로젝트 상세 페이지이며 전체 포트폴리오의 메인 구성은 사용자가 별도로 진행한다. 새 메인/자식 페이지 생성보다 같은 페이지의 본문 압축을 우선한다. 장면·짧은 설명을 펼쳐 두고 코드·원리·검증과 미완료 항목은 토글로 묶었다. 작성 메모는 docs/PORTFOLIO_AUTHORING_NOTES.md에서 관리한다.
- 2026-10-06 최신 원고 요청: 프로젝트 완료 전 최종 포트폴리오의 전체 틀부터 작성한다는 사용자 지시를 기존 작성 순서보다 우선한다. 실제 코드 토글·구체적인 사진/영상/GIF 자리·미완료 기능의 코드/측정/결과 자리를 마련했다. 기능이나 성능 개선까지 완료됐다는 뜻은 아니다. 자료 계획은 docs/PORTFOLIO_CAPTURE_PLAN.md이며 다음 작업은 렌더링 기준 장면과 계측이다.
- 2026-10-06 최신 요청: 3스테이지 흐름 전체를 에이전트가 과제 없이 구현하고 사용자는 최적화부터 참여한다. 이후 포트폴리오 작성에서 설계·원리를 깊게 정리한다. 이번 범위에서 아래의 한 Step씩 과제 규칙보다 최신 요청을 우선한다. 17C/D 구현·Debug 자동 검사는 완료했으며 아트/파티클/UI의 모든 확장이 완료됐다는 뜻은 아니다.
- 2026-10-06 추가 요청: 현재 구현 흐름을 Notion 진행 초안으로 먼저 작성했다. 최종 지원 원고와 성능 결과는 이후 보완한다. 다음 최적화는 렌더링 측정·개선부터 진행하며 Grid 구축 비용 실전 비교는 그 뒤로 미룬다.

- 2026-10-06: 스테이지연결전에공용숲bg0/안개bg1의2레이어스크롤구현·검사완료. 화면확인후1스테이지시간표로복귀한다. 스테이지별배경은추가제작하지않는다.

- 사용자구성구체화:1은적1/적2시간차등장합계약10마리전원처치,2는중간보스,3은적1/적2를소환하는고난도최종보스. docs/STAGE_PLAN.md를진행구성기준으로사용하고최종보스대량탄막을후속최적화측정장면으로삼는다.

- 최신 사용자 진행 요청: 탄환 코어 다음에는다중적/보스/스테이지개념으로이동한다. 개별상태소유권과사망수명→적컬렉션/스폰→보스소환→1~3스테이지순서로한Step씩진행하며추가파티클은이후재개한다.

- 2026-10-05 최신 콘텐츠 범위: 보스의 작은 적 소환,1~3 스테이지와 최종 보스 고난도 패턴을 구현한다. 먼저 Normal/Thin 총알과 효과를 진행한다. 이전 ASSET_PLAN의2스테이지 가정은 초안이며3스테이지 요청으로 대체한다.

- 2026-10-05 사용자 진행 순서 수정: 아트 제작 난이도로 먼저17F 디졸브를 학습하고17E 탄막/이펙트를 보강한다. 여러 단계를 동시에 구현하지 않으며 다중 적/스테이지/패턴/UI 확장은 후속 진행으로 유지한다.
- 2026-10-05 사용자 범위 확장: 정교한 아트, 실제 스테이지, 여러 적/패턴/보스, 탄환·파티클 이펙트, 플레이어/적 디졸브, 타이틀·결과 UI를 먼저 구현한다. 이후 실제 장면으로 렌더링/성능을 개선한다. 기존 단일 보스 버전은 첫 완성본이며 최종 프로젝트 완료가 아니다. 아래 2026-10-04의 빠른 3D 진입 일정은 이 새 요청으로 변경됐고, 3D는 확장 게임과 성능 단계 이후 다시 결정한다.
- 17A~17H도 한 번에 한 Step의 설명→핵심 과제→리뷰로 진행한다. 새 API·셰이더 개념은 먼저 설명하고, 반복 배선/파일/빌드는 에이전트가 처리한다.
- 다중 적 구조를 먼저 마련한 뒤 스테이지 진행을 연결한다. 스테이지 완료는 특정 Enemy 한 개의 HP0이 아니라 남은 웨이브·적·보스 및 진행 상태로 판정한다. 사망 시 게임 판정과 시각 효과 종료/객체 제거 시점을 분리하는 설계를 디졸브 단계에서 다룬다.

- 2026-10-04 진행 방향 합의: 탄막은 HP/무적, 보스 하나, 클리어/실패/재시작까지 작게 완성하고 핵심 검증/기술 기록 후 별도 DX11 3D 학습으로 이어간다. 포트폴리오 최종 문서/모의면접을 3D 진입의 선행 조건으로 삼지 않는다. 3D 핵심 구현은 사용자에게 맡기고 에이전트는 주변 코드/설명/리뷰를 지원한다.

- 2026-10-04 사용자 요청: 단순 호출/배선/반복 설정은 에이전트가 처리하고 빠르게 진행한다. 과제는 새로운 원리 적용이나 설계/디버깅 판단이 필요한 핵심에만 둔다.

- 2026-10-01 사용자 학습 우선순위 반영: Step 8 이후 바로 Object Pool로 넘어가지 않고 8A~8D에서 Graphics/DirectX 기반을 보강한다. Win32 부족한 부분은 실제 입력·resize 등 연결 지점에서 설명/이해 확인한다. 8A 책임 분리 구현과 이해 확인 완료, 다음은 8B.
- Object Pool은 vector만으로도 구현할 수 있으며 컨테이너 교체 자체가 목표가 아니다. 비활성 슬롯 재사용과 측정 가능한 비용 차이를 다루되 현재 게임에 반드시 필요한 최적화라고 전제하지 않는다.
- Step은 숫자 순서대로 진행한다.
- 사용자 이해 확인 없이 다음 Step으로 넘어가지 않는다.
- 필요하면 한 Step을 `0-1`, `0-2`처럼 여러 과제로 나눈다.
- 성능 관련 기능은 가능하면 최적화 전/후 수치를 모두 남긴다.
- 디버깅 이슈는 포트폴리오 소재가 될 수 있으므로 원인과 해결 방식을 기록한다.
- 최종 포트폴리오에서는 단순 기능 목록보다 설계 이유, 트레이드오프, 문제 해결, 성능 수치를 우선한다.
