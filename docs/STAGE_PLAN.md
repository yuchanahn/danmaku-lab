# 3스테이지 전투 구성

2026-10-06 사용자 위임으로 아래 흐름을 구현했다. 수치는 초기 콘텐츠 설정이며 실제 난이도는 플레이 후 조정한다. 최적화와 포트폴리오 정리는 후속 단계다.

| 스테이지 | 등장 구성 | 진행 조건 |
|---|---|---|
| 1 | 0~14초에 적1/적2 각5마리, 총10마리 | 예정 스폰 소진 및 전원 처치·디졸브 후 제거 |
| 2 | HP120 중간보스 즉시 등장 | 처치 후0.8초 디졸브를 마치면3 진입 |
| 3 | HP240 최종보스 즉시 등장, 적1/적2 소환 | 최종보스 처치 후 최종 Clear |

## 책임과 전환

- StageDirector는 시간표와 Running/Transitioning/Complete 진행을 소유한다. 현재 적이0이어도 예정 스폰이 남으면1스테이지를 끝내지 않는다.
- GameScene은 적 생성·충돌·정리를 연결한다. EnemyKind는 Enemy1/Enemy2/MidBoss/FinalBoss이며 개체별 HP·위치·발사쿨다운·생존시간·사망시간을 소유한다. 보스 한 개와 일반 적 vector로 관리한다.
- 일반 적은 Alive→Dying→Removed,0.8초 디졸브 중 이동·발사·피격을 중단한다. 일반 적 사망은 게임 전체 Ending이 아니다.
- 단계 전환 시 탄환과 충돌 Grid를 정리한다. 플레이어 HP·점수·게임시간은 보존하고 자동 회복은 없다. 중간보스 사망 연출 중 전투는 정지하며 Result/BGM 종료로 연결하지 않는다.
- 최종보스 사망 시 탄환을 비우고 살아 있는 소환 적을 Dying으로 전환한다. 기존 Ending0.8초 후 Clear Result로 이동한다. 같은 틱 플레이어 사망은 Failed가 우선이며 모든 단계에서 실패/재시작할 수 있다.
- 전 스테이지에 공용 숲 bg0/안개 bg1을 사용한다. Enemy1.png/Enemy2.png를 적1/2, boss1.png/boss2.png를 중간/최종보스에 매핑한다. 네 시트 모두1024×128/8열×1행/8프레임/12fps이며 원본 색을 유지한다. 별도 공격 시트는 필수가 아니다.

## 패턴 초기값

- 일반 적1: HP6, 아래80px 이동 후 정지,1.5초 간격 조준 보통탄. 적2: HP8, 아래80px 이동 및 좌우 사인 왕복,1.8초 간격 조준3발 얇은 탄.
- 중간보스: 좌우 진폭80/주기5초. HP절반 초과에서는1초 간격 조준9발 부채꼴. 절반 이하에서는0.65초 간격24발 원형+조준5발 부채꼴.
- 최종보스: 좌우 진폭150/주기4초.0.30초 간격 보통탄48발+얇은탄48발을 반대 회전 방향으로 생성하고 매3회 조준7발을 추가한다. HP절반 이하에서는0.20초 간격 각각96발 및 조준11발로 강화한다.
- 최종보스 첫 소환은3초 후 적1/적2 한 쌍, 이후5.5초 간격(강화 시4초). 살아 있거나 디졸브 중인 일반 적을 합쳐 최대8마리다.
- 표시 크기는 Player80×80/일반 적60×60/보스160×160, 판정 반경은5/18/24로 별도 유지한다.
- 시간표는 src/StageDirector.cpp, 보스 패턴은 src/GameSceneStages.cpp, 개체 설정은 src/Enemy.cpp에서 조정한다.

## 검증과 최적화 기준

- Debug 자동 검사: 스폰 중복/조기 전환 방지,1→2→3, HP·점수 보존, 중간 디졸브, 각 단계 실패, 최종 정리, 재시작, 중간 연출과 대량 탄막 실제 렌더 경로 통과.
- 플레이어 충돌을 제외하고 강화 최종보스 패턴을24초 진행한 기능 검사에서 최대 활성탄3230/풀 부족 누락0. 자동 플레이 클리어나 성능 수치가 아니며 난이도/가독성은 실제 플레이 확인이 필요하다.
- 풀 용량8192 및 생성 요청/풀 부족 누락을 기록한다. 슬롯 선형 탐색과 활성탄당 몸체+후광2회 DrawSprite는 유지한다. 탄 생성을 생략한 결과나 용량 확대를 최적화 성과로 기록하지 않는다.
- 같은 패턴·탄수·후광·해상도에서 전후를 비교한다. FPS와 프레임시간, CPU 업데이트/충돌/렌더 제출 및 가능한 GPU시간을 구분하고 실제 병목을 확인한 뒤 배칭/인스턴싱 등의 개선을 선택한다.
