# 최종보스 HP50%: 전체 순회와 Uniform Grid 비교

[원본 CSV](grid-comparison-2026-10-07.csv) · 재현: `./benchmark-stage-fps.ps1 -Grid`

공간분할 도입 여부만 비교하려고 두 경우 모두 최적화 전의 개별 탄환 렌더링을 사용했다. 과거 커밋 전체를 실행한 결과가 아니라 현재 게임에서 충돌 후보 선택 방식을 전환한 실험이다.

## 조건

- Release, NVIDIA GeForce RTX 3080 Laptop GPU, client 1920×1080, Present(0,0).
- 최종보스 HP50%, 무적, 입력 없음, HUD·배경 ON, BGM·디버그 오버레이 OFF.
- 같은 초기 상태를 15초 준비한 뒤 각 방식으로 2초 warmup / 5초 수집. 각 3회, 순서 Linear→Grid / Grid→Linear / Linear→Grid.
- 활성 탄환 2,976~3,216개, 모든 반복 생성 누락 0. 충돌은 60Hz 고정 업데이트에서 수행하며 수집 구간은 300~301틱이다.
- 조회 시간은 플레이어 대 적 탄환의 후보 조회·거리 판정·피격/Graze 처리를 포함한다. Grid 구축 시간에는 풀 순회·셀 비우기·탄환 등록이 포함된다. 플레이어 탄환 대 적의 충돌 처리는 이 타이머 범위에서 제외한다.
- `steady_clock`으로 각 틱의 구축과 조회 구간을 따로 측정한다. 계측은 수집 중에만 켜며 아래 값에는 타이머 자체의 작은 비용도 포함된다.

## 결과

각 지표의 3회 중앙값. 시간은 고정 업데이트 1틱당 CPU 경과 시간이다.

| 지표 | 전체 순회 | Uniform Grid |
| --- | ---: | ---: |
| 검사 후보 수 / 틱 | 3,105.47 | 66.289 |
| 구축 시간 | 0.050µs | 20.684µs |
| 조회·판정 시간 | 20.636µs | 1.344µs |
| 구축 + 조회·판정 | 20.686µs | 21.843µs |
| 게임 루프 FPS | 884.85 | 905.47 |

후보 수는 약97.9%, 조회·판정 시간은 약93.5% 줄었다. 그러나 구축을 포함한 충돌 시간은 약5.6% 증가했다. 합계의 중앙값은 각 항목 중앙값을 더한 값과 다를 수 있다.

| 반복 | 전체 순회 FPS | Grid FPS | 전체 순회 충돌 µs/틱 | Grid 충돌 µs/틱 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 962.16 | 925.77 | 19.530 | 21.757 |
| 2 | 884.85 | 905.47 | 20.686 | 21.843 |
| 3 | 858.66 | 840.91 | 21.196 | 23.991 |

FPS는 반복마다 우열이 바뀌었고 실행 순서에 따라 내려가는 경향도 있었다. 전원·온도·백그라운드 부하를 통제하지 않았으므로 FPS 중앙값만으로 Grid의 성능 향상을 주장하지 않는다. 구축 포함 충돌 시간은 세 반복 모두 Grid가 더 길었다.

## 포트폴리오에 넣을 설명

> 최종보스의 대량 탄막에서 전체 순회와 Uniform Grid를 비교했다. Grid를 사용하면 틱당 검사 후보가 약3,105개에서66개로 줄고 조회·판정 시간도20.64µs에서1.34µs로 줄었다. 하지만 매 틱 Grid를 재구축하는 비용이20.68µs 발생해, 구축을 포함한 비용은 전체 순회보다 약5.6% 높았다. 이 장면에서는 후보 수 감소가 전체 처리 시간 개선으로 이어지지 않았다. 이후 WPA에서 확인한 개별 탄환 렌더링의 반복 Map 호출을 줄이는 인스턴싱을 적용하고 별도로 전후 비교했다.

플레이어 한 곳을 조회하는 현재 조건의 결과다. 조회 대상 수·셀 크기·탄환 분포가 달라지면 이득도 달라질 수 있다. 기본 플레이의 Grid 선택은 이번 측정으로 변경하지 않았다.

인스턴싱의 전후 결과는 [별도 보고서](STAGE_COMPARISON_2026-10-07.md)를 사용한다. 서로 다른 실행에서 얻은 FPS를 합쳐 3단계의 연속 개선율로 계산하지 않는다. 문서의 설명 순서는 공간분할 검증→렌더링 개선으로 구성할 수 있지만, 실제 구현·측정 순서를 그 순서로 바꿔 쓰지는 않는다.

## 검증

Debug·Release 빌드 및 각각 `--smoke-test` 통과. 계측 틱/후보 누적과 종료 후 누적 중단을 자동 검사했다. 아주 짧은 조회는 타이머 해상도에 따라0으로 기록될 수 있어 검사에서는 음수가 아닌지 확인한다. 공식 benchmark 종료0, CSV 6행/동일 반복 탄수 범위/누락0 검증. 수정 전 검사를 통과하지 못한 예비 수집 파일은 이 결과에서 제외했다.
