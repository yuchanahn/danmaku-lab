# 탄환 풀: 전체 순회와 빈 인덱스 최소 힙 비교

[원본 CSV](pool-comparison-2026-10-07.csv) · 재현: `./benchmark-stage-fps.ps1 -Pool`

## 개선 전 구조

8,192개 슬롯을 미리 확보하고 발사마다 `std::ranges::find`로 첫 비활성 슬롯을 찾았다. 동적 탄환 할당은 없지만 앞쪽 활성 구간을 발사마다 다시 확인했다. 충돌/화면 밖 제거는 `active=false`로 처리했다.

## 변경

빈 인덱스를 최소 힙에 보관해 가장 작은 인덱스를 선택한다. 기존 슬롯 선택과 슬롯 순서의 렌더링을 유지하려고 LIFO 스택 대신 최소 힙을 사용했다. 최악의 선택 비용은 O(N)에서 O(log N), 반납은 O(log N)이다. 빈 목록 저장 공간은 풀 용량만큼 처음에 확보한다.

충돌 두 경로와 화면 밖 제거는 `Release`를 공유한다. 이미 비활성인 슬롯은 반납하지 않고, Clear/Reset/방식 전환 때 비활성 슬롯으로 힙을 재구성한다. 풀 슬롯의 외부 조회는 const로 제한했다. 이동·렌더·충돌의 전체 풀 순회와 GetActiveCount는 그대로다.

## 조건

- Release / RTX 3080 Laptop GPU / client1920×1080 / Present(0,0).
- 최종보스 HP50%, 인스턴싱·Uniform Grid 고정, 무적·입력 없음. HUD·배경 ON, 디버그·BGM OFF.
- 동일 상태15초 준비, 각 방식2초warmup/5초수집/3회, 순서 scan→heap / heap→scan / scan→heap.
- FPS6구간은 생성·반납 개별 타이머 OFF. 별도 시간6구간만 타이머 ON. 원본12행의 `pool_timing`이0/1로 구분한다. 서로의 FPS를 섞지 않는다.
- 모든 구간 탄수2,976~3,216/누락0. 시간 수집은 생성4,550회로 모두 같고, 끝1틱 차이로 유효 반납4,552~4,561회다.
- 두 방식 모두 중앙 Release와 상태 검사를 공유한다. 기존 커밋 전체와 비교한 실행이 아니라, 현재 EXE의 슬롯 선택과 반납 목록 관리만 바꾼 대조 실험이다.
- `spawn_ms`는 슬롯 선택·초기화의 CPU 경과 시간 합계, `release_ms`는 유효 반납의 상태 변경·힙 갱신 합계다. 호출별 steady_clock과 통계 기록의 작은 비용을 포함하며, Release의 초기 범위/active 검사와 참조→인덱스 변환은 타이머 범위 밖이다. 프레임 전체나 탄환 업데이트 전체의 시간은 아니다.
- `inspected_slots`는 find가 확인한 활성 플래그 수다. 힙에서는0이지만 인덱스 비교 연산은 존재한다. 검색 결과 위치에서 검사 수를 계산하므로 find 내부에 매 슬롯 카운터를 넣지 않았다.

## 결과

5초 구간 지표의 3회 중앙값이다.

| 지표 | 전체 순회 | 최소 힙 |
| --- | ---: | ---: |
| 생성 요청 | 4,550 | 4,550 |
| 슬롯 활성 플래그 검사 | 7,881,124 | 0 |
| 생성 시간 합계 | 2.4084ms | 0.3800ms |
| 반납 시간 합계 | 0.0834ms | 0.3098ms |
| 생성 + 반납 | 2.4918ms | 0.6898ms |
| 생성당 평균 시간 | 0.529µs | 0.084µs |

생성 시간은 약84.2%, 반납 포함 합계는 약72.3% 감소했다. 힙 반납은 더 비쌌지만 생성의 반복 탐색 감소가 이를 상쇄했다. 합계 절감은 **5초 전체에서 약1.80ms**다.

| 반복 | 전체 순회 FPS·타이머OFF | 힙 FPS·타이머OFF | 전체 순회 생성+반납 ms | 힙 생성+반납 ms |
| --- | ---: | ---: | ---: | ---: |
| 1 | 2313.04 | 2275.84 | 2.1502 | 0.6100 |
| 2 | 2121.26 | 2182.35 | 2.4918 | 0.6898 |
| 3 | 1922.11 | 1894.98 | 2.6162 | 0.8192 |

FPS는 두 반복에서 낮고 한 반복에서 높았다. 실행 중 FPS 하락 경향도 보였으며 전원·온도·백그라운드 부하는 통제하지 않았다. 생성/반납 비용 개선은 확인했지만 전체 FPS의 일관된 향상은 확인하지 못했다. 이 측정 범위의 기존 비용은 작아 주된 프레임 병목으로 보기 어렵다.

이전 인스턴싱/Grid 수집 FPS와 직접 비교해 추가 개선율을 계산하지 않는다. 일반 플레이는 최소 힙을 사용하며, 슬롯 선택 순서는 기존과 같다.
