# 탄환 렌더링 최적화 전후 비교 — 2026-10-07

최종보스 약3,090발 구간에서 개별 렌더 대비 인스턴스 렌더의 FPS가 각 반복에서2.48~2.76배 높았다. 탄환이 적은1·2스테이지에서는 개선이 일관되게 나타나지 않았다.

## 결과

각 방식의3회 FPS 중앙값이다. 배율은 후 중앙값/전 중앙값, 프레임 시간은1000/FPS로 환산했다.

|---|---:|---:|---:|---:|---:|
| 일반 적 | 56~67 | 3,290.99 | 3,601.00 | +9.4% | 0.304→0.278ms |
| 중간보스 | 40~50 | 3,138.43 | 3,043.15 | -3.0% | 0.319→0.329ms |

최종보스의 중앙값 기준 프레임 시간 감소는63.7%다. 아래 같은 반복끼리의 비율과 중앙값끼리의 비율은 계산 방식이 다르다. 중앙값 비율은 서로 다른 반복에서 선택된 대표값의 비교이며, 짝별 향상 배율의 중앙값은 약2.51배다.

전체 반복 FPS 범위는1단계 개별2,821~3,828/인스턴스2,881~3,700,2단계 개별2,936~3,913/인스턴스2,876~3,612,3단계 개별649~846/인스턴스1,632~2,097이다.1·2단계는 개선/역전이 섞였고 반복 편차가 커서 소수 탄환에서도 항상 빠르다고 결론내리지 않는다. 전원/온도/클럭/기타 부하의 원인은 별도 계측하지 않았다.

## 동일 조건 확인

- Release 동일 실행 파일에서 과거 개별 탄환 렌더 전략을 복원해 선택했다. 과거 커밋 전체의 실행 파일을 사용한 것은 아니다.
- RTX3080 Laptop GPU, client1920×1080, Present(0,0), Grid, 무적, 입력 없음, 기본 HUD/배경/안개ON, 디버그 오버레이/BGM OFF.
- 스테이지15초 준비→2초 실제warmup→5초 실제수집, 각 방식3회. 매 반복의 방식 순서를 개별→인스턴스/인스턴스→개별/개별→인스턴스로 반전했다.
- 두 경로 모두 강화 효과ON이다. White 텍스처, 동일 크기·색·Thin 회전·UV·샘플러, 후광 padding16/alpha0.25, 동일 블렌드와 전체 후광→전체 몸체 순서를 소스로 확인했다.
- 18행이 모두 수집됐고 각 스테이지/반복의 두 경로 활성 탄환 최소·최대가 일치했다. 생성 누락은 모두0이다. 탄환 수는 움직이는60Hz 시뮬레이션이라 프레임별 평균은 샘플링 빈도에 따라 조금 다르다.
- 전체 빌드와 Debug/Release 자동 검사를 끝낸 뒤 게임 프로세스 하나로 수집했다. 비교 실행 종료0. 기존 자동 검사에 대량 탄막의 두 렌더 경로 실행을 추가했고 모두 통과했다.

## 해석

개체별 갱신·제출을 묶는 변경은 약3,000발 구간에서 반복 가능한 성능 개선을 보였다. 평균3,090발을 예로 들면 탄환 부분의 기존2N Draw/4N Map은 약6,180 Draw/12,360 Map에 해당하고, 인스턴스 경로는 후광/몸체2 Draw/2 Map이다. 이 호출 수는 소스에서 계산한 값이며 런타임 카운터로 새로 수집한 수치는 아니다.

이번 비교는 배열 재사용·활성 탄환 한 번 순회·CPU 회전 기저·전용 셰이더와 묶음 업로드/Draw를 포함한 최적화 전체의 효과다. Map 또는 Draw 하나만의 개선율이나 GPU 단독 시간으로 해석하지 않는다. FPS는 업데이트·HUD·렌더·Present를 포함한 앱 루프 처리량이며 실제 모니터 표시 프레임 수가 아니다.
